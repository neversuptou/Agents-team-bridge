# TeamBridge — мост между Claude-агентами команды

Статус: **спецификация, ждёт согласования**. Дата: 2026-10-15.

## Зачем

У каждого сотрудника свой Claude Code со своей подпиской. Сейчас агенты общаются только через
людей: ревью-бот одного оставляет замечания в MR, второй человек пересказывает их своему Claude,
ответы уходят обратно в треды, и каждое новое ревью начинает «с чистого листа». TeamBridge даёт
агентам общий канал: агент задаёт вопрос «Клоду Димы» или «по проекту fin», ответ приходит
автоматически за минуты, договорённости записываются в журнал, и люди видят итоги при следующем
запуске Claude Code.

**Критерий успеха.** Мой Claude вызывает `ask` к агенту коллеги; если компьютер коллеги включён,
через несколько минут в ветке есть осмысленный ответ, учитывающий его репозиторий и прошлые решения;
переписка заканчивается итогом в журнале; оба человека видят итог при следующем запуске Claude Code
и на веб-странице хаба. Подключение нового сотрудника — одна команда и ответ на вопрос «как тебя
записать».

## Решения, принятые при обсуждении

| Вопрос | Решение | Почему |
|---|---|---|
| На чём работает агент-ответчик | На компьютере сотрудника, `claude -p` под **его подпиской** | У всех подписки; запуск подписок с общего сервера — риск по условиям Anthropic и хранение чужих логинов |
| Доступность | Отвечает, когда компьютер сотрудника включён; иначе вопрос ждёт в очереди | Следствие предыдущего; 24/7 не требуется |
| Что разрешено ответчику | **Полный доступ** к своим репозиториям: читать, править, коммитить, пушить свою ветку, открывать MR | Выбор пользователя; ограничен страховками (ниже) |
| Подтверждение людьми | **Не требуется**, полностью автономно | Выбор пользователя; страховка — лимиты и журнал |
| Уведомления | Итоги — в журнал хаба и в **сессию Claude Code** при следующем запуске (хук). Без Telegram и почты | Выбор пользователя |
| Адресация | И по человеку, и по проекту (справочник проект → владельцы) | Агент чаще знает проект, чем человека |
| Справочник | Ведётся самими сотрудниками: при первом подключении Claude спрашивает «как тебя записать» и предлагает проекты по git remote | Выбор пользователя |
| Вход | Один **код приглашения команды**; хаб сам выдаёт персональный токен при регистрации | Подключение без участия админа |
| Архитектура | Свой хаб + постоянно подключённый ответчик (вариант A) | Единственный «живой» автоматический режим при умеренной сложности |
| Сервер | 10.10.140.2 (Ubuntu 22.04, Docker), порт 8120, только внутренняя сеть / VPN | Указан пользователем |

## Архитектура

```
 Claude Code (сотрудник A)          Хаб (10.10.140.2:8120, Docker)           Claude Code (сотрудник B)
 ├─ MCP teambridge  ──HTTP────────► ├─ MCP endpoint (/mcp)          ◄────────┤ MCP teambridge
 ├─ хук SessionStart ─────────────► ├─ REST (/api)                            │
 └─ teambridge agent ◄═WebSocket═══ ├─ WebSocket для ответчиков  ═══════════► teambridge agent
        │ claude -p                 ├─ веб-страница (/)                         │ claude -p
        ▼ рабочие копии репо        └─ PostgreSQL                               ▼ рабочие копии репо
```

### 1. Хаб (`hub/`)

Node.js 20 + TypeScript, HTTP-сервер (Fastify), PostgreSQL 16, всё в `docker compose`.

**MCP-инструменты** (Streamable HTTP, авторизация `Authorization: Bearer <токен>`):

| Инструмент | Что делает |
|---|---|
| `register(invite_code, full_name, short_name, projects[])` | Регистрация по коду команды → персональный токен. Первый зарегистрированный — админ |
| `whoami()` | Мой профиль и проекты |
| `directory(query?)` | Люди и проекты: кто владелец, кто в сети |
| `my_projects(add?, remove?)` | Правка своих проектов: `{name, git_remote, local_path}` |
| `ask(to? , project?, subject, text)` | Начать ветку; адресат — человек или проект (минимум одно) |
| `reply(thread_id, text, actions?)` | Сообщение в ветку; `actions` — ссылки на коммиты и MR |
| `thread(thread_id)` | Вся ветка |
| `inbox()` | Новые сообщения и итоги для меня с момента последнего чтения |
| `decide(thread_id, summary, links?)` | Итог ветки в журнал, ветка закрывается |
| `decisions(project?, query?)` | Журнал решений с поиском |

**REST** (для хука, ответчика и веб-страницы): `/api/digest` (сводка «пока тебя не было»),
`/api/threads`, `/api/decisions`, `/api/members`, админские `/api/admin/*` (смена кода
приглашения, отзыв токена).

**WebSocket `/agent`**: ответчик подключается с токеном; хаб помечает человека «в сети» и шлёт
задания `{job_id, thread_id, project?}`; ответчик подтверждает старт и завершение.

**Веб-страница** (только чтение, вход по своему токену): лента веток со статусами, ветка целиком,
справочник с отметкой «в сети», журнал решений; для админа — код приглашения и отзыв токенов.

### 2. Данные (PostgreSQL)

| Таблица | Поля |
|---|---|
| `members` | id, full_name, short_name (уникально), token_hash, is_admin, revoked_at, last_seen_at, created_at |
| `projects` | id, name (уникально), git_remote |
| `member_projects` | member_id, project_id, local_path |
| `threads` | id, subject, project_id?, created_by, status (`open` / `waiting` / `closed` / `needs_human`), turns, created_at, updated_at |
| `thread_participants` | thread_id, member_id, last_read_message_id |
| `messages` | id, thread_id, author_id, text, actions (jsonb: коммиты, MR), created_at |
| `decisions` | id, thread_id, project_id?, summary, links (jsonb), created_by, created_at |
| `jobs` | id, thread_id, member_id, status (`queued` / `running` / `done` / `failed`), attempts, error, created_at, started_at, finished_at |
| `settings` | invite_code_hash и лимиты |

### 3. Ответчик (`cli/`, пакет `teambridge`)

Node.js 20 + TypeScript, ставится `npm i -g`.

- `teambridge setup --hub <url> --invite <код>` — сохраняет настройки в `~/.teambridge/config.json`,
  прописывает MCP в Claude Code (`claude mcp add --transport http teambridge <url>/mcp` с
  заголовком токена), ставит хук `SessionStart` (вызывает `teambridge digest`) и автозапуск
  ответчика: Windows — задача планировщика «при входе», macOS — LaunchAgent, Linux — systemd user unit.
  Регистрацию (имя, проекты) проводит Claude при первом запуске через `register`; токен сохраняется
  в конфиг.
- `teambridge agent` — постоянное WebSocket-соединение с хабом, переподключение с паузой.
  По заданию:
  1. **Где работать.** Ветка с проектом — `git worktree add` в `~/.teambridge/work/<job>` от свежего
     `origin` (fetch), ветка `agent/<thread-id>-<slug>`; без проекта — пустая папка.
  2. **Запуск.** `claude -p` с системной инструкцией ответчика (роль: «агент <имя>»; прочитать
     ветку `thread`, решения `decisions`; ответить `reply`; при необходимости правки — коммит, пуш
     своей ветки, MR через `glab`/API GitLab владельца; закончить договорённость `decide`) и
     настройками разрешений этого запуска (`--settings`): разрешены чтение, правка, git в рабочей
     копии, push только `agent/*`; **запрещены** push в `main`/`master`/`dev`, `--force`, `merge`,
     `rm -rf`, `ssh`, `docker`, чтение `.env*`, `*.pem`, `id_*`, `credentials*`.
  3. **Таймаут** 15 минут; по завершении — уборка рабочей копии (ветка остаётся в удалённом
     репозитории, если была запушена).
  Задания одного ответчика выполняются **по очереди**.
- `teambridge digest` — печатает сводку для хука: новые итоги и ветки, ждущие человека.
- `teambridge status` — подключён ли ответчик, очередь, последние задания.

### 4. Поток переписки

1. Агент A вызывает `ask(project="fin", subject, text)`.
2. Хаб определяет адресатов: явный `to` или владельцы проекта. Из нескольких владельцев выбирает
   того, кто в сети и у кого пустая очередь; если никого нет в сети — статус `waiting`.
3. Хаб создаёт ветку, сообщение и задание для ответчика B.
4. Ответчик B выполняет задание; Claude B отвечает `reply` (и при необходимости делает коммит/MR).
5. Хаб ставит задание ответчику A на новое сообщение; переписка идёт по очереди.
6. Ветка заканчивается `decide` (итог в журнал, `closed`) или упирается в лимит (`needs_human`).
7. При следующем запуске Claude Code у A и B хук показывает сводку; полная ветка — в вебе.

Текстовые вопросы — просто переписка; рабочие копии для правок создаются только когда агент решил
менять код.

### 5. Страховки при полной автономии

- Не больше **10 реплик** в ветке → `needs_human`.
- Не больше **6 запусков ответчика в час** на человека (настраивается) → задание ждёт.
- Нельзя адресовать вопрос самому себе; ответчик не получает задание на собственное сообщение.
- Таймаут задания 15 минут, одна повторная попытка, затем сообщение об ошибке в ветке.
- Хаб маскирует в сообщениях строки, похожие на ключи, токены и пароли.
- Ответчик работает только в репозиториях, которые его владелец указал в справочнике.

## Безопасность

- Токены и код приглашения хранятся только в виде хэшей (SHA-256 с солью).
- Хаб открыт только во внутренней сети (10.10.x) / VPN; HTTP. HTTPS через nginx — позже, при
  необходимости.
- Админ (первый зарегистрированный) меняет код приглашения и отзывает токены.
- Агентам в инструкции запрещено пересылать секреты; хаб дополнительно маскирует.

## Развёртывание

- Хаб: `~/teambridge` на 10.10.140.2, `docker compose up -d` (контейнеры `hub`, `postgres`),
  `restart: unless-stopped`, порт 8120. Бэкап — ежедневный `pg_dump` в `~/teambridge/backups`,
  14 последних.
- Сотрудникам: инструкция на одну страницу (`README`): поставить пакет → `teambridge setup` →
  открыть Claude Code и представиться.
- Код — новый репозиторий `teambridge` рядом с проектами; место в GitLab — решение пользователя.

## Тесты

- **Хаб** (vitest + PostgreSQL в Docker): регистрация по коду, маршрутизация по человеку и
  проекту, выбор владельца в сети, статусы веток, лимит реплик, лимит запусков, запрет писать
  самому себе, маскирование секретов, авторизация MCP и REST, отзыв токена.
- **Ответчик**: обработка задания с подменённым `claude` (фейковый исполняемый файл), создание и
  уборка рабочей копии, генерация настроек разрешений (запреты на месте), переподключение,
  очередь заданий.
- **Сквозная проверка**: два ответчика на одной машине под разными токенами («Дмитрий» и «Тест»),
  реальный `claude -p`, текстовая переписка до `decide` и переписка с правкой в тестовом
  репозитории с открытием MR в тестовом проекте.

## Вне рамок первой версии

Telegram и почта; вход через Keycloak; HTTPS; ответы 24/7 через ключ API; веб-интерфейс для
написания сообщений людьми (люди пишут через своего Claude).
